# AI MIL Trainer — проект навчального Dashboard

## 1. Призначення

AI MIL Trainer — навчальний тренажер для формування практичної AI-грамотності:
користувач вчиться ставити задачі ШІ, отримувати кілька варіантів, оцінювати їх,
знаходити припущення та ризики, перевіряти результат і лише після цього приймати
власне рішення.

> ШІ є помічником, а не остаточним джерелом істини. Результат має перевіряти людина.

## 2. MVP

Перша версія не потребує локальної великої AI-моделі.

Модулі:
1. Dashboard — прогрес, навички, останні результати.
2. Навчання — короткі уроки простими словами.
3. Тренажер — практичні завдання.
4. Генерація альтернатив — не менше 5 різних підходів.
5. Оцінювання — ризик, реалізованість, час, перевірюваність.
6. Критична перевірка — сильні/слабкі сторони, можливості/загрози,
   припущення, суперечності, пропущені ризики, альтернативні пояснення.
7. Checklist — послідовна перевірка повноти.
8. Профіль навичок — де користувач помиляється найчастіше.

## 3. Основний цикл завдання

Постав задачу
-> згенеруй щонайменше 5 варіантів
-> не ранжуй їх на етапі генерації
-> оціни за критеріями
-> знайди слабкі місця
-> знайди припущення
-> знайди ризики
-> визнач, яких даних не вистачає
-> перевір факти
-> людина приймає рішення.

## 4. Режими

### GENERATE
Мета: ширина пошуку.

Правила:
- мінімум 5 альтернатив;
- уникати дублювання;
- не давати рейтинг;
- чітко позначати невідоме;
- не вигадувати факти.

### EVALUATE
Мета: порівняння вже створених варіантів.

Критерії:
- Risk — 0..10, менше краще;
- Feasibility — 0..10;
- Time — 0..10, швидкість реалізації;
- Verifiability — 0..10.

Система показує характеристики, але не оголошує політичного, оперативного
чи іншого рішення «найкращим». Остаточне рішення залишається за людиною.

## 5. Критична перевірка

Для кожної пропозиції формуються:
- Сильні сторони;
- Слабкі сторони;
- Можливості;
- Загрози;
- Припущення;
- Суперечності;
- Пропущені ризики;
- Альтернативні пояснення;
- Невідомі дані;
- Що потрібно перевірити людиною.

## 6. Структура Dashboard

Головна:
- % проходження курсу;
- карта навичок;
- останні завдання;
- слабкі навички;
- рекомендований наступний урок.

Навчання:
- рівень;
- модулі;
- урок;
- приклад;
- міні-вправа;
- підказка;
- перевірка.

Тренажер:
- умова;
- поле задачі;
- Generate;
- Evaluate;
- Critical Check;
- Checklist;
- Human Review.

Результат:
- оцінки;
- знайдені ризики;
- припущення;
- невідомі;
- альтернативи;
- рішення користувача;
- кнопка «Я перевірив результат».

## 7. Навчальна програма

1. Що таке ШІ.
2. Що ШІ вміє і де може помилятися.
3. Як правильно поставити задачу.
4. Контекст і обмеження.
5. Робота з текстом та таблицями.
6. Генерація альтернатив.
7. Оцінювання варіантів.
8. Критичне мислення.
9. Прогнозування через сценарії.
10. Ризики, безпека та перевірка.
11. Практичні навчальні сценарії.
12. Підсумкова атестація.

Для військового середовища навчальні приклади на MVP мають бути синтетичними
(навчально змодельованими), без реальних оперативних даних, цілей, маршрутів,
живих координат або іншої чутливої інформації.

## 8. Оцінювання слухача

Навички:
- AI basics;
- постановка задач;
- робота з контекстом;
- генерація альтернатив;
- критичне мислення;
- перевірка фактів;
- оцінка ризику;
- сценарне прогнозування.

Оцінка формується з виконаних вправ, а не тільки з тестів.

## 9. Підказки

Рівні:
1. Легка підказка.
2. Напрямок думки.
3. Частковий приклад.
4. Розбір помилки.
5. Повне рішення.

Мета — допомогти користувачу навчитися, а не виконати завдання замість нього.

## 10. Технічний напрямок MVP

Через обмежені ресурси ПК:
- легкий web Dashboard;
- локальна база навчального контенту;
- просте API для AI-запитів;
- можливість працювати без AI у режимі тестів та навчальних матеріалів;
- модуль AI має бути відокремлений від навчальної логіки.

Не прив'язувати архітектуру до одного AI-провайдера.

## 11. Контроль ризиків

Перед виконанням AI-запиту перевіряти:
- чи немає зайвих або чутливих даних;
- чи зрозуміла мета;
- чи дозволений такий тип використання;
- чи є джерела;
- чи потрібна перевірка людиною.

Після відповіді:
- позначити неперевірені твердження;
- перевірити ключові факти;
- показати невизначеність;
- зафіксувати людську перевірку.

## 12. Принципи

Архітектура навчання орієнтується на:
- законність;
- відповідальність та підзвітність;
- пояснюваність і відстежуваність;
- надійність;
- керованість;
- зменшення упередженості.

Це є узгодженим напрямком із публічними принципами відповідального AI
NATO та підходом NIST AI Risk Management Framework.

## 13. Майбутні версії

V1: Dashboard + курс + тренажер + оцінювання.
V2: AI Tutor + адаптивні завдання.
V3: сценарний симулятор.
V4: адміністратор/викладач + групова статистика.
V5: сертифікація та аудит навчальних результатів.

## 14. Критерії готовності MVP

MVP вважається готовим, якщо користувач може:
1. пройти урок;
2. виконати практичне завдання;
3. отримати щонайменше 5 різних варіантів;
4. оцінити їх за заданими критеріями;
5. знайти ризики та припущення;
6. пройти checklist;
7. зафіксувати власну перевірку;
8. побачити, як змінився його профіль навичок.

## 15. Невизначеність

Точні строки, вимоги до обладнання, доступність конкретних AI-сервісів,
правила роботи з даними та організаційні вимоги мають бути підтверджені
перед практичним впровадженням. Цей документ є проєктною схемою, а не
нормативним документом.
